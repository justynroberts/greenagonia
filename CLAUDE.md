# CLAUDE.md — Greenagonia

Greenagonia is PagerDuty's fictional demo company. One repo, two deployment
modes: single-user (one laptop, one PD account) and shared (hosted site,
multi-user).

## Layout

```
greenagonia/
├── Makefile              # build CLI, generate scenarios.json, sync site
├── quickstart.sh         # prereqs + build (+ optional deploy)
├── README.md             # single-user quickstart
├── ADMIN-GUIDE.md        # shared environment admin guide
├── cli/
│   ├── go.mod
│   ├── main.go           # deploy / undeploy / scenarios / web / site-url
│   └── site/             # gitignored — generated by make build
├── site/                 # storefront source (static site)
│   ├── index.html
│   ├── chaos.js          # chaos engine; fetches scenarios.json at runtime
│   ├── scenarios.json    # generated by make build; committed for static hosting
│   └── ...
├── terraform/            # single-user Terraform
└── terraform-shared/     # shared/multi-user Terraform
    └── ...               # state and *.auto.tfvars.json are gitignored
```

## Single source of truth for scenario data

`cli/main.go` is authoritative. `make build` runs `scenarios dump-json` to
write `site/scenarios.json`, then copies `site/` → `cli/site/` and compiles
the binary with it embedded. Never edit `cli/site/` directly — it is
regenerated on every build.

## Deployment modes

| Mode | Who | How |
|---|---|---|
| Single-user | One person, own PD account | `./quickstart.sh` → `./greenagonia deploy` → `./greenagonia web` |
| Shared/hosted | Many people, one shared PD account per admin | Deploy `terraform-shared/`; host `site/` on any static server; give each user `?pdkey=<routing_key>` URL |

## Key commands

```bash
make build                          # generate scenarios.json, embed site, compile CLI
./greenagonia deploy --env demo # provision PagerDuty via Terraform
./greenagonia web --env demo    # serve storefront locally, open browser with keys
./greenagonia scenarios list    # list available scenarios
./greenagonia scenarios run --env demo --scenario bad-payment-deploy
./greenagonia scenarios resolve --env demo
```

## Contract: site ↔ CLI

The site fires identical events to the CLI:
- Same dedup key format: `greenagonia/{env}/{scenario}/{service}/{step}`
- Same `custom_details` payload (merged from `common`, `service_meta`, `shared`)
- `?pdenv=` URL param must match the CLI `--env` for resolve to work from either side
