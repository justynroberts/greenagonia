# CLAUDE.md — Greenagonia

This is the **shared, multi-admin** Greenagonia demo environment. Single-user
deploy/undeploy/web/scenarios-run commands no longer exist. Everything here
is oriented around a shared PagerDuty account with one stack per admin.

## Build flow

```bash
cd greenagonia && make build
```

Two steps, in order:

1. `go run . scenarios dump-json > ../site/scenarios.json`
   Exports scenario definitions from `cli/main.go` (the single source of
   truth for all scenario data) into `site/scenarios.json`.

2. `go build -trimpath -ldflags "-s -w" -o ../greenagonia .`
   Compiles the binary to `./greenagonia` (repo root).

`make build-all` cross-compiles for macOS arm64/amd64, Linux amd64/arm64,
and Windows amd64.

Never edit `site/scenarios.json` by hand — it is regenerated on every
`make build`.

## Key CLI commands

```bash
greenagonia setup                           # first-run wizard
greenagonia token                           # set/replace PD REST API token
greenagonia user-token                      # set PD user-level token (Slack)
greenagonia slack-token                     # set Slack bot token
greenagonia admin add JR "Name" e@mail.com  # add or update an admin
greenagonia admin remove JR                 # mark for removal on next deploy
greenagonia admin list                      # list configured admins
greenagonia deploy                          # terraform init + plan + confirm + apply
greenagonia destroy                         # destroy entire environment
greenagonia urls [INITIALS]                 # per-admin storefront links and keys
greenagonia site-url [URL]                  # show or set storefront base URL
greenagonia slack-channels                  # create {ini}-incidents Slack channels
greenagonia scenarios list                  # browse available scenarios
greenagonia scenarios dump-json             # export scenario data as JSON
```

There are no `run`, `resolve`, or `web` commands. The storefront drives all
incident scenarios.

---

## Contract: site ↔ CLI (scenarios.json)

`cli/main.go` is the authoritative source for scenario data. `make build`
exports it to `site/scenarios.json`, which the storefront fetches at runtime
via `chaos.js`. The storefront uses this file to display scenario names and
descriptions.

The storefront fires the `bad-payment-deploy` scenario — the same payload
shape as the CLI would have used, including `custom_details.service =
"payment-gateway"`. Each admin's orchestration router matches that bare service
name and routes to their prefixed service (`{INI}-payment-gateway`).

## Architecture notes

- **Binary output:** `./greenagonia` (repo root, alongside Makefile).
- **State:** `state/` (gitignored). One person applies at a time.
- **Secrets:** `terraform-shared/secrets.auto.tfvars.json` (chmod 600,
  gitignored). Never committed.
- **Config:** `terraform-shared/config.auto.tfvars.json` (gitignored).
  Contains admins map, time zone, site URL, feature flags.
- **Initials collision:** CLI auto-derives alternatives (`JR → JRO → JROB`).
- **Per-admin plan scope:** adding or removing one admin touches only that
  admin's ~60 resources; all others are untouched.
- **Restricted Access role:** each admin sees only their own stack plus the
  shared personas. The Terraform operator token sees everything.
- **No per-service change event integrations** in this environment. Change
  events are posted by the storefront's chaos engine.
